# 发票 XML × 应收单 自动匹配复核 · 原型

一个**纯前端、可直接在浏览器打开**的交互原型，用于演示《发票 XML 与应收单自动匹配及人工复核 PRD》的核心逻辑。

> ⚠️ 本模块承担**核销台账**职责：确认匹配即生成核销记录（含发票 × 应收单配分明细）并入库，支持**反核销**撤销，形成「核销 → 反核销 → 重新核销」完整闭环；台账为核销事实的唯一来源。
> 本期范围**不含**会计凭证生成与 ERP 总账回写，由下游系统对接。详见 [`docs/核销台账PRD-v1.0.md`](docs/核销台账PRD-v1.0.md)。

---

## 快速开始

直接双击打开 `index.html`（无需服务器、无需依赖）。

推荐浏览器：Chrome / Edge（≥103，导入 Excel 依赖浏览器原生 `DecompressionStream`）。

**首次使用建议流程**：`④ 应收单池` →「加载内置示例（模板结构）」或上传模板文件 → `① 发票导入` →「加载全部示例发票」→ `② 匹配复核` 确认匹配（高置信可**一键批量确认**）→ `③ 核销台账` 查看批次 / 明细 / **历史结算** / **汇总对账**，或发起反核销。

> 💾 **数据持久化**：发票池、应收单池与核销台账均保存在**本机浏览器**（IndexedDB，不可用时降级 localStorage / 内存），刷新 / 重开浏览器不丢；首次打开自动装入内置示例应收单，「清空应收单池」「重置演示数据」等状态同样持久化。清浏览器缓存 / 换浏览器会丢数据，请定期用「导出台账（CSV）」留档。

## 按模板导入财务应收单

`④ 应收单池` 页顶部提供「导入财务应收单（按模板）」：

| 操作 | 说明 |
|------|------|
| 选择模板文件 | 支持 `.xlsx` / `.csv`，可多选；`.xlsx` 由内置零依赖解析器直接读取（不引入任何三方库）。把 `samples/应收单模板示例.csv` 与 `samples/客户档案示例.csv` **一起选中**即可看到税号自动补全 |
| 加载内置示例（模板结构） | 用内置数据按模板结构生成 10 张应收单（A~E 场景 + 红字冲销 + `AR-H1`/`AR-H2` 历史已结算示例）+ 客户档案，可直接跑通全部匹配场景 |
| 下载导入模板（CSV） | 导出带示例数据的模板，便于线下填写 |
| 清空应收单池 | 清空当前应收单（含示例数据） |
| 金额口径 | **不含税（金额）** / 含税（应收金额），默认不含税，与发票「不含税金额」同口径 |
| 导入前清空应收单池 | 勾选后先清空再导入（默认勾选，避免与示例数据混淆） |

**模板结构**（对齐项目根目录 `数据模板-财务应收单.xlsx` 的工作表「**列表数据**」）：

| 行 | 内容 |
|----|------|
| 第 1 行 | 中文字段名表头（69 列） |
| 第 2 行起 | 数据行 |

> 解析按**字段名**识别列，**列顺序可调整**、可增删无关列；表头行在前 15 行内自动定位（取命中已知列名最多的一行）。

**字段映射（模板 → 原型应收单）**

| 原型字段 | 模板列 |
|----------|--------|
| 应收单号 | `单据编号`（为空时自动编号 `AR-IMP-xxxx`） |
| 客户 | `往来户` |
| 客户税号 | 模板**无此列**，由另选的「客户档案」（`编码` + `统一社会信用代码`）补全 |
| 金额 | 默认取 `金额`（不含税）；切换口径后取 `应收金额`（含税）；也可按 `税额`/`数量`×`单价` 反算 |
| 剩余余额 | `未结算折本币` / `未结算金额`（有值时）；无值且无「已结算金额」时视为全额未核销 |
| 数据源已结算（历史已结算） | `已结算金额(本位币)` / `已结算金额`（有值时优先）；无该列时按 `主金额 − 未结算` 反算 → 写入台账「历史结算」行，并口径化为应收单「已核销」 |
| 合同编号 | `合同号` → `合同(编)号` 的**原值** |
| 其他留存字段 | 单据类型/状态、单据日期、到期日、结算组织、部门、产品线、款项用途、款项性质、税率、税额、结算状态、核销状态、备注等 |

**数据完整性（重要）**

- 所有字段**原样保留**，**不删除 `-`、`(`、`)`、`·` 等任何字符**，例如合同号 `24-TSM348S228-CP189`、备注 `冲销-AR-L14-20251231-196805` 均按原文存储。
- 每行导入时另存一份**完整原始字段**（表头名 → 原值），在应收单池中**点击任意行即可展开查看全部字段**。
- 合同号仅在与发票比对时使用「规范化比较键」（去空格/连字符并大写）；该键只用于匹配，**不影响存储与展示的原值**。发票侧备注中提取的合同号同样保留原值。

**导入行为**

- 同一「单据编号」重复导入会被拦截并在提示区列出。
- 金额为空或为 0 的行不导入，并在提示中汇总行数。
- 金额为负的**红字/冲销**单据正常导入并保留原值，但不参与自动匹配。
- 导入后的应收单「来源」列为 `模板导入`，与示例数据 `示例` 区分；后续匹配、复核、核销逻辑完全复用。

## 演示场景（对应 PRD 验收标准）

点击「① 发票导入」→「**加载全部示例发票**」，即可一次性看到全部场景：

| 场景 | 示例发票 | 对应应收单 | 预期结果 |
|------|----------|-----------|----------|
| **A** 单对单 · 高置信 | `10000001` 星辰 ¥10000 | `AR-A1` ¥10000 | 税号一致 + 差额 0 → **高置信，自动预绑定**，可一键确认 |
| **B** 一对多 · 合并开票 | `10000002` 博远 ¥8000 | `AR-B1` ¥5000 + `AR-B2` ¥3000 | 自动**推荐组合**，人工确认 |
| **C** 金额容差 · 中置信 | `10000003` 华南 ¥5000.50 | `AR-C1` ¥5000 | 差额 0.5 元 → **降级中置信，标红差额** |
| **D** 多对一 · 拆分收款 | `10000004`+`10000005` 恒通 ¥4000×2 | `AR-D1` ¥8000 | 自动**推荐组合**，人工确认 |
| **E** 多对多 | `10000006`+`10000007` 联创 ¥6000×2 | `AR-E1` ¥7000 + `AR-E2` ¥5000 | **不自动组合**，仅列候选，人工圈选 |
| **重复导入** | 再导一次示例 A | — | 按「发票代码+号码」**拦截**，提示已存在 |

### 手动验证：批量确认 / 部分核销

- **批量确认**：加载全部示例发票后，`② 匹配复核` 顶部出现绿色工具条「一键确认全部高置信（N）」，点击后按当前匹配结果逐笔入库（场景 A 单对单，以及差额为 0 的 B / D 推荐组合），完成后跳转 ③ 页可见多个批次；任一笔入库校验失败会在该处中止，已成功的批次保留。
- **部分核销**：
  1. 先导入场景 **C**（华南 ¥5000.50）。
  2. 在「匹配复核」页对中置信的 `AR-C1` 点「确认匹配」→ 生成核销记录，`AR-C1` 剩余余额归 0。
  3. 想看部分核销：在未匹配池（如场景 E）勾选一条金额小于应收单余额的发票手动关联，即可看到应收单变为「部分核销」，剩余余额保留并在后续匹配中继续参与。
- **刷新不丢**：导入 / 核销后直接按 F5 刷新页面，发票、应收单（含原始字段）、台账记录均保留；发票核销状态与应收单余额由台账有效记录自动重算。

## 核销台账（含反核销闭环）

台账在「匹配复核」页点「一键确认 / 确认匹配 / 手动关联所选」时**自动写入**，在 `③ 核销台账` 查看：

| 能力 | 说明 |
|------|------|
| 配分明细 | 每笔核销按「发票 × 应收单」逐行配对（`pairKey = invoiceId:arId`）；点击台账行展开，可见每行**核销前 / 后余额**。抵充顺序固定（发票按金额降序、应收单按到期日升序），尾差归入余额最大的一行，保证 Σ明细 = 核销总额 |
| 只追加不删除 | 记录写入后不可修改、不可删除；纠错一律走反核销 |
| 反核销（无审批） | 台账行 →「反核销」→ 原因码（+备注）→ 生成反向记录（金额取负、`refBatchNo` 指向原批次、明细逐行取负、`pairKey` 不变），原记录置「已反核销」，应收单余额回滚、发票回到「待匹配」重新参与匹配；同一记录**只能反核销一次**（禁链式） |
| 金额守恒 | Σ明细 = 台账核销总额；`已核销 + 剩余余额 = 原金额`（容差 0.01 元）；反核销后余额与发票状态由台账中**有效记录**重算（`arWrittenOff()`），不依赖前端缓存 |
| 入库二次校验 | 写入前重新读取台账校验应收单余额（`AR_BALANCE_CHANGED`）与发票唯一性（`INVOICE_ALREADY_WRITTEN`） |
| 幂等 | 同一 `idempotencyKey` 重复提交只入库一次，重复请求返回原记录 |
| 历史已结算同步 | 数据源（应收单池 `已结算金额 / 未结算金额`、外部接口、上传 JSON/CSV）→ 台账 `entryType = HISTORY` 的「历史结算」行；按应收单号去重（外部源优先）、整体刷新，不计入余额 / 有效核销净额、不可反核销 |
| 自动刷新 | 按间隔（关闭 / 5 / 10 / 30 秒）比对变更指纹 `Store.signature()`，有变化才重新查询渲染；切换页签、页面重新可见、其他标签页写入（`storage` 事件）时立即重查，等效于网页端实时查库 |
| 查询 / 导出 | 关键字（批次号 / 发票号 / 应收单号 / 客户 / 合同号）、状态、类型（核销 / 反核销 / **历史结算**）、来源、业务日期区间筛选 + 分页；「导出台账（CSV）」按当前筛选导出**明细行级**数据（含已反核销与历史结算记录） |
| 汇总对账 | ③ 页底部「📊 汇总对账」折叠面板：**按客户**（有效核销净额 / 反核销发生额 / 历史已结算分列）、**按会计期间**（核销 / 反核销 / 净额 / 历史结算）、**应收单余额对账表**（逐行校验 原金额 = 已核销 + 剩余余额，不平标红，BR-04）；基于台账全量记录，不受当前筛选影响（FR-13） |
| 批量确认 | `② 匹配复核` 顶部工具条一键确认全部高置信匹配（单对高置信 + 差额为 0 的推荐组合），逐笔入库、逐笔二次校验，失败即中止 |
| 期间关账 | 原核销所属期间已关账时禁止直接反核销（`PERIOD_CLOSED`）。可在控制台 `await Store.setPeriodClosed('2026-09', true)` 模拟 |
| 持久化 | **发票池 + 应收单池 + 核销台账**均优先存 **IndexedDB**（DB v2），不可用自动降级 localStorage / 内存，`③` 页右上角显示当前存储方式。刷新 / 重开不丢；发票核销状态、应收单余额等派生值启动时由台账有效记录重算。数据**仅存本机**，清缓存 / 换浏览器会丢，请定期导出 |

**手动验证闭环**：`④` 加载内置示例 → `①` 加载全部示例发票 → `②` 一键确认场景 A → `③` 台账出现批次 `HX…-001`（1 行明细）→ 点「反核销」填原因 → 台账新增反向批次、原批次变「已反核销」、`④` 页 `AR-A1` 余额回到 ¥10000 → `②` 页该发票重新出现，可再次核销。

**后端对接**：设置 `window.WRITEOFF_API_BASE = 'https://host/api'` 即切换为 HTTP 存储（`store.js` 的 `HttpStore`，含台账与发票池 / 应收单池接口，契约见 PRD §12.2），UI 无需改动。

## 历史已结算数据同步（台账自动更新）

`③ 核销台账` 页顶部提供「**历史已结算数据（数据源同步）**」卡片：把**数据源**中已经结算过的数据同步为台账里的「**历史结算**」行，
并按设定间隔自动刷新，页面呈现方式与「网页端查数据库」一致。

| 数据源 | 说明 |
|--------|------|
| ① 应收单池（默认开启） | 模板列 `已结算金额` / `已结算金额(本位币)` 有值时直接作为已结算额；无该列时按 `未结算折本币` / `未结算金额` 反算（`已结算 = 主金额 − 未结算`）。导入应收单后自动同步 |
| ② 外部接口地址 | 填 URL → 「立即拉取」，或勾选「定时拉取」+ 间隔（10 / 30 / 60 / 300 秒）自动轮询（跨域需允许 CORS） |
| ③ 上传文件 | JSON / CSV，一次性导入后作为本机快照数据源持续参与同步（示例：[`samples/历史已结算数据示例.csv`](samples/历史已结算数据示例.csv)） |

**同步规则**

- 三类记录按**应收单号**去重，**外部数据源（接口 / 文件）优先**于应收单池派生值；每条应收单最多一条历史结算记录。
- `Store.replaceHistory(records)` **整体刷新**快照行（旧快照行被替换），保证台账历史数据与数据源一致。
- 汇总单独展示：`有效核销净额`（本系统核销事实）与 `历史已结算（数据源）`互不混算。
- 外部记录与应收单池 `已结算金额` 不一致时会给出提示（台账历史行以外部数据源为准）。
- 权限边界：历史结算行**不占用应收单余额**（余额口径已体现在应收单池「已核销」中）、**不可反核销**；纠错请修正数据源后重新同步。
  台账「只追加不删除」约束仅适用于本系统的核销 / 反核销记录。

**外部记录字段**（JSON 支持数组或 `{ records: [ … ] }`；字段名兼容中文表头与英文键名）

| 字段 | 别名示例 |
|------|----------|
| 应收单号 | `应收单号` / `单据编号` / `arNo`（必填） |
| 已结算金额 | `已结算金额` / `已核销金额` / `结算金额` / `settledAmount` / `settled` / `amount`（必填，> 0） |
| 结算日期 | `结算日期` / `业务日期` / `settleDate` / `bizDate` / `date` |
| 客户 / 合同编号 / 应收金额 | `客户` · `合同编号` · `应收金额`（可选） |
| 结算单号 / 核销状态 / 备注 | `结算单号` · `凭证号` · `核销状态` · `备注`（可选） |

**验证方式**：`④` 加载内置示例（含 `AR-H1` 部分核销 ¥5000、`AR-H2` 已核销 ¥8000）→ `③` 台账出现 2 行「历史结算」；
再上传 `samples/历史已结算数据示例.csv` → 台账历史行变为 4 行（含不在应收单池中的历史应收单 `AR-OLD-0007`）。

## 功能与 PRD 映射

| PRD 章节 | 原型实现位置 |
|----------|-------------|
| 3. 输入与字段口径 | `app.js` → `readInvoiceNode()` / `INV_FIELDS` / `extractContract()`（数电票 + 通用 Invoice 双格式） |
| 3. 应收单输入 | `app.js` → `readXlsx()` / `buildArDocs()` / `applyArImport()`（按《数据模板-财务应收单.xlsx》导入） |
| 4.1 匹配优先级 | `computeMatches()` 优先级打分（税号 > 合同 > 金额） |
| 4.2 置信分档 | `tier` 判定 + 复核页色块（高/中/未匹配） |
| 4.3 金额容差 | `TOL_HIGH=0.01` / `TOL_MAX=1` |
| 4.4 多对多 | `findCombos()` 子集和 + 未匹配候选列表 |
| 批量确认 | `app.js` → `confirmAllHigh()`（高置信逐笔入库，失败即中止） |
| 6. 状态机 | 发票状态 / 应收单状态字段；池数据持久化后由台账有效记录重算（`restorePools()` / `persistPools()`） |
| 池持久化（v1.2） | `store.js` → `savePools()` / `loadPools()` / `isPoolsReady()`（IndexedDB v2 新增 `invoices` / `ars` 存储，HttpStore 预留 `/pools`）；`app.js` → `persistPools()` / `restorePools()` |
| FR-13 汇总对账（v1.2） | `app.js` → `renderLedgerReport()`：按客户 / 按会计期间汇总 + 应收单余额对账表（BR-04 逐行校验） |
| 7. 核销台账 / 反核销 | `app.js` → `allocatePairs()`（配分）/ `buildWriteOffRecord()` / `confirmGroup()` / `reverseWriteOff()` / `refreshLedger()`；`store.js` → `Store`（IndexedDB 持久化、幂等、余额二次校验、期间校验、CSV 导出）。规则见 [`docs/核销台账PRD-v1.0.md`](docs/核销台账PRD-v1.0.md) |
| 7. 历史已结算同步 / 台账自动刷新（v1.1） | `app.js` → `arHistoryRecord()` / `externalHistoryRecord()` / `syncHistoryLedger()` / `histMismatchLines()` / `tickLedger()`；`store.js` → `Store.replaceHistory()`（快照行整体刷新）/ `Store.signature()`（变更指纹）。PRD → §6.4、BR-12~14、FR-16/17 |
| 8. 异常分支 | 重复导入拦截、合同提取失败降级、标记异常、外部数据源解析失败 / 跨域提示、历史行与数据源差异提示 |

## XML 字段映射说明

支持两类发票 XML，自动识别、无需选择：

**① 数电票（根节点 `<EInvoice>`，推荐来源）** —— 结构化取值：

| 逻辑字段 | 数电票路径 |
|----------|-----------|
| 发票号码 | `TaxSupervisionInfo/InvoiceNumber` |
| 购买方名称 | `EInvoiceData/BuyerInformation/BuyerName` |
| **购买方税号** | **`EInvoiceData/BuyerInformation/BuyerIdNum`** |
| 销售方名称 / 税号 | `SellerInformation/SellerName` / `SellerIdNum` |
| 不含税金额 | `BasicInformation/TotalAmWithoutTax`（多明细时为合计） |
| 税额 | `BasicInformation/TotalTaxAm` |
| 价税合计 | `BasicInformation/TotalTax-includedAmount` |
| 开票日期 | `TaxSupervisionInfo/IssueTime` |
| 备注 | `EInvoiceData/AdditionalInformation/Remark`（从中提取合同编号） |
| 明细行 | `IssuItemInformation`（`ItemName` / `Quantity` / `UnPrice` / `Amount` / `TaxRate` / `ComTaxAm`），可多行 |

> 数电票没有「发票代码」，故该列显示 `-`；去重按「发票代码 + 发票号码」，同一份文件重复导入仍会被拦截。

**② 通用 `<Invoice>` 平铺结构**（如 `samples/` 下示例）—— 宽松匹配（标签名包含即识别）：

| 逻辑字段 | 识别的标签候选（任意命中） |
|----------|--------------------------|
| 发票代码 | `InvoiceCode` / `发票代码` / `fpdcode` |
| 发票号码 | `InvoiceNumber` / `InvoiceNo` / `发票号码` / `fphm` |
| 购买方名称 | `BuyerName` / `购买方名称` / `gmfmc` |
| 购买方税号 | `BuyerIdNum` / `BuyerTaxNo` / `BuyerTaxId` / `购买方纳税人识别号` / `购买方税号` / `gmfnsrsbh` / `nsrsbh` |
| 销售方名称 / 税号 | `SellerName` / `SellerIdNum` / `销售方名称` / `销售方税号` |
| 不含税金额 | `TotalAmWithoutTax` / `不含税金额` / `AmountExclTax` / `AmountWithoutTax` / `合计金额` / `金额` / `Amount` / `je` / `hjje` |
| 税额 / 价税合计 | `TotalTaxAm` / `税额` / `ComTaxAm`；`TotalTax-includedAmount` / `价税合计` |
| 开票日期 | `IssueTime` / `开票日期` / `发票日期` / `InvoiceDate` / `kprq` |
| 备注 | `Remark` / `备注` / `bz` |

其他说明：

- 一个文件内可含**多张发票**（多个 `<Invoice>` 或 `<EInvoice>`），会全部导入。
- 所有取值**原样保留**，不做裁剪（含 `-`、`·`、`（）` 等字符）。
- 合同编号从备注按正则 `合同\s*[编号]{0,2}\s*[：:]\s*([A-Za-z0-9\-_·]+)` 提取，全角/半角冒号均可（如数电票备注 `合同编号：24-TSM261S170-CP131；…`）。
- 匹配用的合同号「规范化比较键」仅用于比对，不影响存储与展示的原值。

**遗留业务待确认**：

- **应收单金额口径**：模板同时提供 `金额`（不含税）与 `应收金额`（含税），原型默认取不含税以对齐发票「不含税金额」，
  并提供界面上切换；需财务确认最终口径。
- **客户税号来源**：`数据模板-财务应收单.xlsx` 不含客户税号列，原型通过另选的「客户档案」（`编码` + `统一社会信用代码`）补全；
  若正式环境无法关联，税号仅用于去重，匹配降级为合同号+金额。
- **剩余余额口径**：`未结算折本币` 为空时原型按「全额未核销」处理，需确认空值是否代表已全额结算；
  模板同时提供 `已结算金额` 时原型**优先采用**该列作为数据源已结算额（未结算列仅在无已结算列时用于反算）。
- **历史已结算数据源**：应收单池 `已结算金额` 与外部接口 / 上传文件不一致时，原型默认以**外部数据源为准**并给出差异提示，需财务确认权威来源与责任方。详见上文「历史已结算数据同步」。
- XML 具体来源格式与字段映射。
- 金额容差阈值（0.01 / 1 元）需财务最终确认。
